# 7주차: k-means, 차원의 저주, 삼각부등식 가지치기

이번 과제에서는 k-means를 직접 구현해 초기화 방식에 따라 결과가 얼마나 달라지는지 비교했고, 차원이 커질 때 거리 분포가 어떻게 바뀌는지 측정했다. 마지막으로 삼각부등식으로 불필요한 거리 계산을 건너뛰면서 baseline과 똑같은 클러스터링 결과를 얻는 방법을 구현했다.

## 1. 진행 방식

과제 분석 → 구현 계획 → 구현 → 검증 순서로 진행했고, 단계마다 결과를 확인한 뒤 다음 단계로 넘어갔다. observation.md에 필요한 측정은 과제 파일을 수정하지 않는 별도 스크립트로 실행했다.

## 2. Task 1: k-means와 k-means++

과제에서 요구한 5개 함수(`euclidean`, `assign`, `update`, `kmeans`, `sse_of`)를 구현했다. 빈 클러스터가 생기면 예전 중심을 유지하기 위해 `update`에 선택 인자 `previous`를 추가했고, `previous` 없이 빈 클러스터가 생기면 조용히 넘어가지 않고 에러를 내도록 했다. Task 3 baseline의 `_means`와 같은 처리 방식이다.

거리가 같으면 번호가 낮은 중심을 고르고, 수렴 여부는 실수인 중심이 아니라 정수인 레이블로 판정했다. k-means++는 거리 제곱 가중치의 누적합을 직접 계산해 중심을 뽑았고, 시드별 재현을 위해 전역 random이 아닌 `random.Random(seed)`만 사용했다. `max_iter < 1`이면 반복이 한 번도 돌지 않아 레이블이 비게 되므로 시작할 때 에러를 내도록 했다.

결과는 verify 7/7 통과였고, 40개 시드에서 세 덩어리를 찾은 횟수는 random 24회, ++ 40회였다. 자세한 측정과 해석은 observation.md에 정리했다.

## 3. Task 2: 차원의 저주 측정

Task 2는 새 코드를 작성하지 않고 제공된 스크립트를 실행했다. 결과 파일 curse.json은 실행할 때마다 누적되므로 같은 조건은 한 번만 실행했다.

| 구분 | 조건 | 목적 |
| --- | --- | --- |
| 기본 측정 | dim 2~200 / points 1000 | 차원 증가에 따른 mean, contrast, rel.sd 변화 |
| 고차원 측정 | dim 500, 1000 / points 2000 | 더 높은 차원에서도 거리 집중이 이어지는지 확인 |
| A6 측정 | dim 50 / points 250, 4000, 16000 | 차원을 고정하고 점의 수의 영향 비교 (1000은 기본 측정 결과 사용) |

```bash
python3 task2_curse.py --dims 2,5,10,20,50,100,200
python3 task2_curse.py --dims 500,1000 --points 2000
python3 task2_curse.py --dims 50 --points 250
python3 task2_curse.py --dims 50 --points 4000
python3 task2_curse.py --dims 50 --points 16000
```

contrast는 dim 50에서 처음 1 아래로, dim 200에서 처음 0.5 아래로 떨어졌고 평균 거리는 √d에 비례했다. 표와 A2~A8 해석은 curse.md에 정리했다.

## 4. Task 3: 삼각부등식 가지치기

점마다 현재 중심까지의 거리 상한과 다른 중심까지의 거리 하한을 하나씩만 저장했다(점당 2개). 중심별로 하한을 두면 점당 13개가 필요해 갱신 부담이 커지기 때문이다. 상한·하한과 중심 간 거리로 현재 중심이 계속 가장 가깝다는 것이 보장되면 다른 중심까지의 거리 계산을 건너뛰고, 중심이 움직이면 이동량만큼 bound를 갱신해 항상 올바른 범위를 유지하게 했다.

동점 처리(`d < best - 1e-12`)와 종료 순서(중심 갱신 후 종료 판정)는 baseline과 똑같이 맞췄다. 계산을 줄였더라도 소속이나 종료 시점이 달라지면 같은 알고리즘을 빠르게 만든 것이라고 볼 수 없기 때문이다.

| 항목 | baseline | 내 구현 |
| --- | --- | --- |
| 거리 호출 | 10,320,000 | 1,222,968 (88.1% 절감, strong) |
| SSE | 10,737,882.9445506874 | 10,737,882.9445506874 (차이 0) |
| 반복 횟수 | 43 | 43 |
| 실행 시간 | 23.21초 | 4.08초 |

43번의 반복 모두 레이블이 baseline과 같았다. bound별 기여도와 첫 반복 비중은 observation.md에 정리했다.

## 7. 이해한 것과 어려웠던 것

k-means는 같은 데이터라도 시작 중심에 따라 결과가 달라진다. random으로 시작해도 반복하면서 회복하는 경우가 있었지만 항상 그렇지는 않았고, ++는 초기 거리 계산을 더 쓰는 대신 시작점을 넓게 골라 이번 데이터에서 항상 세 덩어리를 찾았다. 또 점마다 클러스터를 하나씩 만들면 SSE를 0으로 만들 수 있으므로, SSE가 작은 것과 클러스터링이 유용한 것은 다르다는 점도 알게 됐다.

차원의 저주는 평균 거리가 작아지는 것이 아니라, 평균 거리는 커지는데 거리들의 상대적인 차이가 줄어드는 현상이었다. 가까운 점과 먼 점이 점점 비슷한 거리로 보인다는 점이 핵심이다.

가장 어려웠던 부분은 중심이 움직인 뒤에도 상한과 하한이 올바른 범위를 유지하도록 갱신하는 것이었다. bound가 틀리면 소속이 바뀌어야 할 점까지 건너뛰게 된다. 삼각부등식으로 증명된 경우만 건너뛰는 것과 가까워 보여서 건너뛰는 것은 다르다는 점, 그리고 같은 결과를 얻으려면 동점 처리와 종료 순서까지 맞춰야 한다는 점을 이해했다.
